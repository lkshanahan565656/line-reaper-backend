LINEREAPEROPEN THE APP

Developers

Public API and widgets

The same numbers the app shows, as JSON and as widgets for your own page: best prices above the fair, line moves, the public record, league boards and feed status. Read-only, and the same for everyone.

  • Nothing here places a bet, and nothing is sized or set up per person: every caller gets the same data.
  • Every row carries the label the app gives it. PROVEN appears only where RESULTS proves it (50 graded at one venue, CLV t of 2 against Pinnacle's close); everything else is a LEAD or research.
  • Prices are what each feed showed at its last read. Check the price at the venue before you bet.

Get a key

One key is enough for a site. It is shown once: copy it somewhere safe. We keep only a hash of it.
The key saved in this browser

Using it

Send the key in an X-API-Key header (or as ?key= where a header is awkward). Any site may call it from a browser: CORS is open to every origin.

curl -H "X-API-Key: lr_…" https://line-reaper-backend-production.up.railway.app/api/v1/best-prices?league=nfl
  • Limits: 60 calls a minute and 5,000 a day (UTC) per key. Every answer says where you are in X-RateLimit-Remaining, X-RateLimit-Reset (seconds) and X-RateLimit-Daily-Remaining. Over the limit is a 429 with Retry-After. Counts restart when the server redeploys.
  • Caching: each answer has an ETag. Send it back in If-None-Match and an unchanged answer is a 304 with no body. Most data changes about once a minute.
  • Errors are JSON: {"error":{"code":"…","message":"…"}} with 400 (bad parameter), 401 (no key or an unknown one), 404 and 429.
  • New keys: at most 5 an hour from one address.
  • Versioning: fields may be added to v1; none are renamed or removed. A change that would break a caller becomes v2.
  • Widgets need no key and allow 120 loads a minute per visitor address.

Each side's best bettable price that sits above Pinnacle's no-vig fair, after the venue's fee, with the second-best price, what an exchange book fills, and the label the app gives it (PROVEN or LEAD).

ParameterWhat it does
leagueone league key, e.g. nfl, nba, nhl, ncaaf
marketmoneyline, spread, total or player_prop (comma list)
venueonly this venue (e.g. kalshi, betrivers)
minEvminimum EV in percent after fees, default 0
minSizedollars every exchange price must fill, fee in
hoursgames starting within this many hours (default 48)
statetwo-letter US state code, e.g. TX: only venues a source says a resident can use
limit1 to 200, default 50

Discord feed

Run a Discord server? Paste a webhook and your channel gets the same public posts as everyone else, each with its share card: the weekly record digest (Mondays 13:00 UTC), record changes on RESULTS (a kind newly proven, no longer proven, losing to the close, or reaching 50 graded; checked hourly), and today's biggest line moves (daily 21:00 UTC).

  1. In Discord: Server Settings > Integrations > Webhooks > New Webhook. Pick the channel, then Copy Webhook URL. You need the Manage Webhooks permission.
  2. Make a key above (it is saved in this browser), paste the URL below and tap CONNECT. A welcome post lands in the channel straight away.
  3. To stop: tap DISCONNECT, revoke the key, or delete the webhook in Discord.
  • Every channel gets the same posts. Nothing is sized, picked or set up per person, and nothing places a bet.
  • A post says proven only of what RESULTS marks proven, and shows a profit only where RESULTS does.
  • One webhook per key. The URL is stored encrypted and never shown again; a webhook Discord says is gone, or 5 failed posts in a row, stops the feed.
Needs a key from this page, saved in this browser.

With code: PUT /api/v1/feed/discord with {"url":"…"}, GET /api/v1/feed and DELETE /api/v1/feed/discord, each with your X-API-Key.
